# CK 滚动恢复稿产品合同 v1

状态：Internal。适用于 CK 1.0 本机桌面工程恢复；不是公开交换格式、版本管理系统或跨机器同步协议。

## 1. 术语

- **正式工程**：用户最近一次成功保存到磁盘的 `.ck`、`.maker` 或受管理工程目录。
- **磁盘基线**：正式工程内容哈希及其可验证修改时间。
- **有效恢复稿**：结构、完整状态哈希、工程身份和磁盘基线均通过校验，并且比正式工程更新、内容与当前正式工程不同的滚动稿。
- **打开工程会话**：从一次打开或重新加载某个工程开始，到离开、关闭或再次打开该工程为止。
- **所选稿**：本次自动提示中实际展示给用户的那一份恢复稿。

## 2. 存储与选择

1. 普通语义编辑约 12 秒防抖保存；同一完整状态和磁盘基线不重复写入。
2. 每个工程最多保留 3 份滚动稿，另受单稿、单工程和全局字节预算约束；损坏稿隔离，不参与候选选择。
3. 自动提示只选择当前工程**最新的一份有效恢复稿**。旧稿只是有界安全冗余，不是自动恢复队列；关闭一个提示后不得立刻串行弹出下一份旧稿。
4. 候选比较绑定磁盘基线和完整状态哈希，不依赖全局 `clean_shutdown` 标记，也不因仅存在恢复稿就宣称上次进程崩溃。

## 3. 同一会话内的提示规则

- 选择“暂不处理”只关闭提示，不删除磁盘文件；本次打开工程会话内，所选稿以及同一磁盘基线下更旧的稿件均不再自动提示。
- 成功“覆盖当前工作区”后采用相同的会话抑制规则。所选稿继续保存在磁盘，直到该工程完成一次正式保存；这样在正式保存前再次崩溃时仍有恢复依据。
- “放弃恢复稿”只删除所选稿。它不会修改正式工程，也不会在当前对话框后自动弹出下一份旧稿。
- 成功“恢复为新工程”只在新工程已经原子保存后删除所选稿；用户取消选择路径或保存失败时必须保留原稿。旧稿不自动级联提示。
- 关闭并重新打开原工程会建立新会话，可以再次按“最新有效稿”规则提示。若磁盘基线已变化，旧基线稿不得冒充当前候选。

会话抑制只是 UI 提示策略，不是删除、归档或完整性证据；它不得写入恢复稿文件来伪造新的编辑状态。

## 4. 覆盖当前工作区

顺序必须保持：

1. 检查未知积木和恢复稿身份；失败时工作区与恢复稿都保持不变。
2. 创建 `before_restore` 正式检查点；检查点失败时停止覆盖。
3. 完整反序列化积木、板卡选项和生成源码，并把工程标记为未保存。
4. 关闭本次提示并登记会话抑制；此时不删除所选稿。
5. 用户随后正式保存成功时，清理该工程的滚动恢复稿并刷新磁盘基线。正式保存失败或清理失败不得谎称稿件已经删除。

## 5. 故障与并发边界

- 最新候选在 `list` 与 `load` 之间消失或被隔离时，本轮提示可以安全结束；不得加载错误 ID、错误工程或未验证字节。
- 未知积木、板卡包不一致、检查点失败、反序列化失败和另存失败均不得提前删除所选稿。
- 多窗口可能同时保存或清理稿件，因此删除允许幂等；UI 不能把“文件已不存在”解释成工作区已经恢复。
- 正式保存后的全项目清理与逐条“放弃”是不同操作，二者都必须按工程路径隔离。

## 6. 最低验收

1. 同一基线存在两份以上有效稿时，只自动展示最新一份，且不会自动串联旧稿。
2. “暂不处理”和成功覆盖后，同一打开工程会话内不因板卡、选项或组件重算重复弹窗；重新打开工程后允许再次提示。
3. 覆盖成功后所选稿仍存在；正式保存成功后该工程稿件清空，保存失败时一个不删。
4. “放弃”只删除精确 ID；“恢复为新工程”在取消或失败时保留、成功时才删除所选稿。
5. 未知积木和检查点失败路径不修改工作区、不删除恢复稿。
6. 后端继续验证最多 3 份、内容去重、项目隔离、损坏隔离和全局预算。
