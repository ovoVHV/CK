# CK 图形化库批量制作工具箱

作者：CKYAN。先从一个可运行的样板开始，换成自己的驱动和积木；每个成品独立导入。

| 样板 | 重点 | 用来验证定位的错误 |
| --- | --- | --- |
| `ck_button_latch` 按钮消抖 | 声明引脚来自 PIN 输入，使用内部上拉，区分按住和刚按下 | 消抖时间 0，改为 25 ms |
| `ck_beat_clock` 非阻塞定时器 | 一个 millis() 周期定时器，轮询时消费事件，可以停止 | 周期 0，改为 250 ms |
| `ck_sample_mean` 滑动平均 | 数值表达式输入，浮点结果，窗口未满时按实际数量计算 | 窗口 17，改为 4 |

**要用库：** 在 CK 选择板卡，打开「库管理器 → 导入」，选择单个 `ck_…-1.0.0.zip`。解压后 `examples/demo.ck` 是正常工程，`examples/invalid.ck` 专门用来看报错。三个演示的工程板卡为 Uno；未上传，不代表真实按钮或其他硬件已验证。整套作者工具箱 ZIP 不能当成单个库导入。

**要造库：** 把工具箱整个解压。`packages/` 是展开后的三套成品；`recipe/` 是重建它们的 Python 3.9+ 配方；`schemas/` 是 CK 的正式协议。`recipe/build.py` 接受一个尚不存在的输出目录；它是这三种样板的制作配方，做新设备时需要同时更换 API、驱动、描述与示例逻辑。也可以直接按 `packages/` 的结构手工制库。标准库就能打包和做第一轮检查：

```powershell
py -3 recipe/build.py ./new-batch
py -3 recipe/check.py ./new-batch
node tools/preflight.mjs ./new-batch/packages
```

`check.py` 面向这套带「数值填错」抽测的交付约定；其他错例（例如类型或资源冲突）应扩展相应断言。`preflight.mjs` 适用于普通 CK 包，检查生成器占位符、输入和目录。两者都不能代替 JSON Schema、CK 导入、真实编译或硬件试验。`evidence/` 是本批的实际记录。

**可以直接发给其他 AI 的任务：**

> 为清单里每个设备制作一个独立 CK 库 ZIP。核对驱动头文件与 API；将完整原库及所有非 Core 依赖按原目录放进 `libraries/<原库>/`，保留子目录、来源、版本与许可。已有原库不要拆成几个散文件。外层必须有唯一 `library.json.id`、`ck-blocks.json`、积木定义、声明式生成规则和工具箱分类。按现有 schema 写明输入、输出、初始化顺序、引脚从哪里取、是否共享、适用板卡及未知限制。为普通用户提供一个能打开的 `.ck` 正例。为声称支持的诊断提供一个只改一处的 `.ck` 反例，写明目标积木 ID、预期错误和如何修复。只把真实编译或实物观察过的结果列为通过；对不支持或没测试的情况如实说明。

**报错怎么做：**

1. 第三方作者不需要写红框、感叹号、跳转代码，也不必为每种错误编写文案。`errors` 可以为空，作者也不要生成 `.ck-quality-report.json`。CK 会把能映射到生成源码的编译错误定位回积木。独立驱动内部错误、链接错误或尚未获得源码位置的错误，不能保证定位到唯一积木。
2. `errors` 给人和 AI 解释原因与恢复办法，本身不会执行校验。这三个样板把**明确限定为常量的配置项**在对应积木生成的 C++ 语句中做 `static_assert`，给出稳定错误码与范围。样本值和按钮引脚依然可以是表达式。新设备不要把所有动态参数一律限定为常量。现有 CK 中，红框警告可能给出通用说明，具体错误码和范围在编译诊断的原始信息里。
3. 验收必须走「导入 ZIP → 打开正常工程并产生固件 → 打开错误工程并编译 → 核对正确的积木 ID、红框、警告图标、定位 → 改对后取消标记并再次生成固件」。真机行为需另测。

仓库配套的 `tests/desktop-library-batch.mjs` 是此流程的实际桌面回归。要对新一批运行，可把工具箱 `tools/desktop-library-batch.mjs` 放到 CK V9.1 源码仓库的 `tests/`（需要同目录 `desktop-client.mjs`）；将 `CK_LIBRARY_BATCH` 指向新输出目录，通过 `scripts/Start-Preview.ps1 -EngineConfig <测试配置> -PreviewExe <预览EXE> -Harness <测试脚本> -CdpPort <空闲端口>` 启动。本机需已有目标 Core。使用独立测试数据目录，桌面会安装被测库；脚本拒绝覆盖同 ID 且源码不同的库。
