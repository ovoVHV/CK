# V9.1.0-alpha.2 产品候选

V9.0.0-alpha.1 位于独立基线仓库，原标签及桌面 EXE 保留。V9.1 使用独立源码、安装目录、应用身份和运行目录，不改变 v6 默认路径，不注册工程文件关联。

本轮交付当前用户安装器：固定 Node 24.13.0（与官方发行摘要核对）、Ninja、Arduino CLI、Rust 资产校验器及 Windows Job 管理器。不依赖系统 Node、Ninja、PATH 或 PowerShell 7。Microsoft 签名的 WebView2 安装引导程序作为独立修复入口提供，不强行安装或降级现有运行时。

启动器优先探测 Documents/CK 和本机 Arduino15 中的 ESP32 Core 3.3.6 或 3.3.6-cn；也可通过 CK_V91_ASSET_ROOT 指定用户资产目录。缺少目标工具链时，普通桌面保留兼容后端；“准备工具链”入口通过随包 Arduino CLI 安装指定 Core 到用户目录，不建立服务或请求管理员权限。

ESP32 家族按实际 FQBN 和完整菜单参数路由，不固定 Flash、分区、PSRAM、USB 或 CPU 配置。目录版本标签兼容 3.3.6-cn，但仍核验平台 recipe 内容、真实工具/SDK 路径，以及所有输入的完整 SHA-256。按安装的 boards.txt 选择芯片工具链和所有可选 SDK 代际，并核验展开后的路径被完整资产集合覆盖。特殊库或未接管的平台规则保持明确的安全回退。此能力不等于所有板卡、库和菜单笛卡尔积已经完成发布资格。

稳定工程 ID 与源码指纹分别传递。修改代码不会创建新 V9 工作目录；切换工程或重新打开工程会分离工作区。取消上下文和工程上下文都显式传入专用编译线程。普通兼容后端保留稳定临时根目录，V9 会话仍使用独立命名空间和内存授权。大小检查使用平台的原始 size 工具、section 规则和当前分区/RAM 限额。

No-Op 必须同时满足会话授权、相同源码、构建上下文、完整资产身份、Sketch 目录成员，以及完整 build/graph 文件内容和目录成员身份。每次成功请求仍做资产前后两轮完整 SHA-256。相同源码路径跳过调度器和重复规则收据重建，但仍重新读取构建成果，并由宿主独立验证及导出十个交付文件。磁盘收据、时间戳或自校验清单不产生授权。任何命中资格不足均回到正常调度；取消、失败及进程终止撤销会话权限。

同一次源码编辑的额外成本也必须记录：No-Op 身份首次捕获会完整读取 build/graph，而不是免费得到摘要。对应计时为 noOpAuthorityCaptureMs；命中计时为 noOpOutputValidationMs。总收益只以实测桌面 IPC 为准。

GNU ld 及其参数保持原样。G3 收据优化默认关闭。无免哈希资产授权，无跨工程 PCH/对象共享。T1 会话边界不抵抗任意恶意同用户进程。

第二台运行“第二台资格测试”，执行 30 次新编辑、20 次历史恢复、20 次相同源码，并包含冷构建、准备构建和官方 clean 对照。使用隔离的 WiFi 库副本形成 73 编译单元基准，不向用户库目录安装测试库。所有样本留存；机器信息、原始收据及阶段成本会自动压缩到 %LOCALAPPDATA%/CKBuildEngineV91。

发行门槛分别为新编辑 P95≤20秒、历史恢复中位数≤10秒、相同源码中位数≤5秒。至少两台机器各自通过，才进入 V9.2 RC。V9.3 完成生命周期、兼容性及安装资格；V9.4 才能在批准后成为默认。安装包可交付不等于上述资格已通过。

卸载只删除本安装器列出的应用文件和快捷方式，不递归删除用户数据；保留工程、工具链和测试记录。运行中的 V9.1 会话阻止安装/卸载覆盖。
