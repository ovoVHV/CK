# 用 CK AI 制作积木库

适用版本：9.1.0-alpha.39。

主聊天现在可以连续处理补库：先搜索当前板卡已加载的库，确实缺少底层能力时制作最小库，质量检查和真实试编译后自动安装、加载并继续原工程任务。无需切换模式。安装记录单独保存到聊天；工程修改仍以预览确认应用，补库不会自动修改或上传工程。

遇到加载失败，未提交的安装回滚；用户取消时，已完成安装的库仍保留并如实记录。切换工程、板卡、修改积木或同时改变其他库会停止当前任务。库编译与工程编译分别最多3次，每次主聊天最多补2个库，仍受总时间、工具与上下文预算限制。不能继续时明确报告缺失信息，不把库完成当成工程完成。

用户也可以单独制作库：

打开编程页 AI 侧栏，选择“制作积木库”。当前板卡和 Core 必须已经就绪。描述硬件的确切型号、需要的操作、参数、返回值、单位和初始化要求；已有底层驱动时提供接口资料。AI 无法从硬件名称推断所有协议。

默认开启“验证通过后自动安装并加载”。可关闭后先检查候选，点击“安装并加载”再启用。验证失败或停止任务不会修改当前工程。成功后，库进入当前板卡的库目录，积木进入工具箱与搜索；点击“用这个库搭建程序”可让 AI 使用刚加载的真实积木结构。

制作流程：按需读取库规范 → 分段暂存 → 检查 JSON、字段、连接、占位符和 v2 声明 → 隔离真实编译 → 失败读取诊断并最多修复两次 → 安装 → 核验运行时注册、搜索目录与内容身份。加载失败撤回安装。草稿不会直接覆盖已有库。

每个包有独立标识和版本，包含 `library.json`、`ck-blocks.json`、`blocks/blocks.json`、`blocks/ck-generator.json`、`blocks/toolbox.json`、说明与试编译示例；必要时增加 `src/*.h/*.hpp/*.c/*.cpp` 和 `library.properties`。`.ck-quality-report.json` 由 CK 生成，不交给模型伪造。

可导出 ZIP，其他用户通过库管理器导入。新库创建器不自动升级或覆盖已有包；已有包的版本升级和工程迁移沿用库管理器。生成库可以在库管理器卸载。候选验证授权不跨软件重启恢复；已经正式安装的库按正常库加载规则持久保留。

首版每次最多 24 个积木、16 个源文件，分段每次最多 8 个；草稿正文上限 240KB。主聊天按需开放库工具，补库结束后收起；解释请求不能制作或安装库。格式和硬件契约按需读取，草稿由程序精确保留，局部修复只替换对应积木或文件。

只试编译当前完整板卡配置以及默认或显式样本参数。编译通过不代表真机通过、所有参数组合通过或跨架构兼容。缺少硬件资源声明时保留“未知”，不推断无占用。首版不生成任意 JavaScript、mutator 或远程资源，也不自动下载依赖。

安装和回滚继承当前桌面的 T1 信任边界，不宣称抵抗任意恶意同用户进程。库源码与能力资料会发送到用户选择的模型服务，模型费用按服务商计费。

库加载后会重新核对之前已查询的积木结构。临时工作区的变量按名称和类型比较，不把随机变量编号当作变化；真实字段、连接或其他库内容变化仍会停止任务。

库声明先在本地按正式JSON Schema校验，格式错误返回具体字段路径，便于局部修正；这些尚未执行编译器的错误不占用三次真实编译额度，但仍受整个任务的轮次、工具和时间预算约束。
