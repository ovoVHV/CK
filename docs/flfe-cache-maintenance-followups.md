# FLFE 缓存维护后续项

状态：CK 1.0 之后的 P1，不阻塞当前编译正确性与公平 A/B。

- 关机协调：退出软件时等待或取消尚未开始的延迟缓存清理，并为已经进入扫描的任务保留明确的完成上限与日志证据。
- ENOSPC 恢复：编译器或打包工具明确返回磁盘空间不足时，执行一次紧急缓存回收（上限不高于 512 MiB），然后只重试可证明幂等的准备阶段；不得自动重试 Flash 写入。
- A/B 维护租约：正式 native A/B runner 后续应在整个配对窗口显式暂停普通缓存维护，并把租约 epoch 写入报告，防止用户同时发起的普通编译在 native lane 期间产生额外磁盘 I/O。当前 runner 已保证 qualification 本身不调度维护，但还没有跨命令的全局租约。
- LRU 配对与访问收据：源码目录 `CK_Builds/sketch_*` 与 out-of-tree 构建目录 `CK_Builds/build/sketch_*` 应通过机器可读身份成对计量、成对淘汰，并记录最近一次真实 Exact／编译访问时间，避免只删除一侧后留下孤儿缓存或误删常用缓存。现阶段已确保 `build` 容器不会被整树删除，但尚未实现跨目录配对淘汰。
- 跨平台磁盘证据：Windows 的卷剩余空间和 reparse-point 分支已有实编与测试；macOS/Linux 的 `statvfs`、符号链接和退出时任务行为仍需进入 CI 与原生冒烟，不能从 Windows 结果外推。

这些优化不能跳过工具链身份、依赖闭包、产物清单、SHA-256 或上传前真机门禁。
