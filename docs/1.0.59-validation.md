# V1.0.59 验证记录

Windows 普通用户；两个版本分别运行自己的桌面、启动脚本、控制器及工具。每板每版都使用新的工作目录，相同源码、核心和编译任务上限。计时从点击编辑器编译按钮到进度层关闭且按钮可再次点击。不清 Windows 文件缓存，不含核心下载或烧录。

| V1.0.59 交付包 | 首编 | 改码 | 原样 |
| --- | ---: | ---: | ---: |
| Uno / AVR 1.8.8 / Wire | 5.10 s | 2.56 s | 1.08 s |
| ESP32-S3 / 3.3.6-cn / WiFi | 57.69 s | 17.97 s | 3.02 s |

同轮 .58、按场景的样本量与未通过资格判定的 P95 见 [原始汇总](1.0.59-button-comparison.json)。Uno 先跑 .58，S3 先跑 .59。各格一个样本，不代表全部板卡、其他机器或 P95。首编实际编译 28 / 71 个对象；改码均编译 1 个，原样均为 0。核对导出固件和收据的 SHA-256，并验证 S3 合并镜像中嵌入本次应用。未进行真机烧录。

此前一个候选在 S3 CN 首编用了 79.60 秒：光输入校验就花了 23.57 秒，同时打开文件的等待是主要开销。另一次同候选首编 59.30 秒，不能把差值全算作代码收益。交付版本把新会话首编恢复到配置的完整扫描策略，已有会话再使用 .57 的校验调度，两种都完整验证内容。没有以 WiFi 库名作优化条件，也未更改系统安全设置或关闭动画。

旧版长路径判断遗漏多字节字符。用中文父目录复现 GCC 输出文件创建失败和 Ninja `Filename longer than 260 characters` 后，缩短独占创建的临时目录名，并按 UTF-8 字节数选择 Ninja 的相对路径。使用与交付包哈希相同的桌面、引擎、工具和启动脚本，在最长 Ninja 输入 **262 字符**的目录完成首编 **60.26 秒**、改码 **19.45 秒**、原样 **3.07 秒**。这不是对任意路径长度的承诺。

安装包 `CK-V1.0.59-Setup-x64.exe`：60,217,248 字节，SHA-256 `fd2bee74909c16022f2ce05a91e08aba773d7abada8ba38780d1eea4317122df`。解包后校验 705 个文件。安装包无 Windows Authenticode 签名，更新清单使用 Ed25519 签名。分别用 .57/.58 隔离数据验证了手动覆盖安装所用的存储初始化路径保留原工程及核心；未覆盖用户当前安装。旧更新器不会自动升级到数字较小的 1.0.59。
