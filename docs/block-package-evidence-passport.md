# CK 积木库轻量证据护照 v1

状态：Stable local。护照由当前 CK 安装依据本机可复核事实即时计算，不是发布者签名、云端证书、综合评分或 CK 官方推荐。

## 目的

证据护照把分散在质量报告、v2 语义清单和安全运行边界中的结果放到同一处，让用户能快速判断一个积木库目前“证明了什么、还缺什么”。缺少证据显示为“待验证”，不能伪造为通过，也不等同于失败。

## 五个阶段

| 阶段 | 可验证输入 | 通过条件 | 无证据时 |
| --- | --- | --- | --- |
| 结构检查 | CK Package Quality Report | 积木库结构、入口、路径和内容身份通过当前本机门禁 | 待验证 |
| 语义元数据 | `ck-blocks.json` v2 | 每个积木包含语义、依赖、输出、硬件、生成、约束、示例和错误八类元数据 | v1 显示需复核；缺清单显示待验证 |
| 安全运行边界 | 声明式入口、内容哈希与运行时复核 | 仅激活通过复核的声明式 JSON；不执行 Legacy JavaScript | 待验证或已阻止 |
| 真实编译证据 | 与包内容、完整 FQBN、Core、工具链绑定的 compile-only 凭证 | 当前版本尚未自动签发可移植凭证 | 待验证 |
| 真板证据 | 与具体板卡、配置和包内容绑定的运行记录 | 当前版本尚未自动签发可移植凭证 | 待验证 |

护照显示 `已验证阶段数 / 5`，但不计算百分制或“健康分”。任一确定性失败会显示“已阻止”；警告或待验证显示“需关注”。

## 证据边界

- 内容 SHA-256 只能证明所检查内容未变化，不能证明作者身份。
- Schema 与静态质量报告不能证明物理传感器、时序、接线或运行结果正确。
- compile-only 不等同于上传或真板验证。
- 本机通过不自动升级为 CK 官方认证、推荐包或许可证法律意见。
- 包内容、质量规则、FQBN、Core 或工具链变化后，依赖旧身份的证据必须重新判断，不能静默沿用。

## 1.0 数据来源

前端依据 `LibraryInfo` 中的 `quality_report`、`block_manifest`、声明式入口与运行时激活结果即时构建护照。1.0 不允许包作者在 ZIP 中自行填写“已通过编译”或“真板已验证”来提升护照等级；未来如引入独立凭证，必须单独定义签发者、内容绑定、过期与撤销规则。
