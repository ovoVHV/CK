# 上一个可用版本与工程诊断包

## 上一个可用版本

CK 只在普通固件上传成功、上传产物清单再次验证通过，并且 ESP32 明确报告芯片与实体 Flash 后更新“上一个可用版本”。调试固件和运行轨迹固件不会覆盖该记录。保存失败只会产生警告，不会把已经成功的上传改判为失败。

一个可用版本包含：

- 完整 Blockly JSON、同一时刻生成源码、板卡与菜单配置；
- 独立 `ck.lock`，记录 Core、Arduino CLI、工具链、完整 FQBN、构建签名、编译档案、实际优化和依赖；
- ESP32 分区定义及 SHA-256；
- 每个烧录段的角色、地址、大小和 SHA-256；
- 上传时明确读取到的芯片、实体 Flash 与明确报告的 PSRAM；
- Flash/RAM 资源统计和编译警告数；
- 编译与上传日志；
- 本次实际使用的 CK 托管外部库完整恢复副本。

本地提交使用暂存目录和原子重命名。界面只读取能够再次通过工程、`ck.lock`、分区、依赖目录和固件哈希检查的最新记录；损坏或不完整的目录不会显示成可恢复版本。

### 四项操作

1. **与当前工程比较**：解释积木增删改、源码、Core、完整 FQBN 菜单、优化、依赖版本、真机证据和资源变化。
2. **恢复工程**：先创建恢复前保护检查点，再恢复积木、源码和配置，不写 Flash。
3. **恢复固件**：保持当前工程不变，重新通过现有上传门禁后烧录保存的固件。
4. **完整恢复**：先保护工程，恢复 CK 托管依赖，再恢复固件和工程配置。不同依赖会先备份；Core 版本不一致时阻止并要求用户先在核心管理器准备对应版本，不会静默联网安装或降级。

ESP32 恢复固件比普通上传更严格：芯片族或实体 Flash 无法明确确认时直接阻止。所有恢复仍重新校验完整 FQBN、构建签名、分区定义、烧录地址、文件大小和 SHA-256。

当前完整固件恢复覆盖已启用严格上传产物清单的 ESP32 与 AVR 目标。其他架构不会伪造烧录地址或保存不完整固件集；在对应上传清单规则完成前只保留原有工程检查点能力。

## 工程诊断包

“工程诊断包”只生成用户选择位置的本地 ZIP，不连接网络、不上传源码，也不自动创建 Issue。

导出范围：

- 包含完整工程；
- 仅包含生成源码；
- 不包含源码，只包含环境、清单和日志。

四项隐私保护默认全部开启：

- 隐去 Wi-Fi 名称、密码和常见口令；
- 隐去本机用户名；
- 隐去绝对路径；
- 不包含串口内容。

ZIP 使用受限相对路径、文件数量与容量上限，并记录每项是已包含、缺失还是按用户范围省略。导入另一台电脑时只在本地验证清单和 SHA-256，然后生成中文摘要，包括板卡、Core、完整 FQBN、Flash、失败阶段、源码范围，以及当前电脑是否缺少对应 Core。
