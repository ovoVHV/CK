# 源码库静态归档回归（2026-11-28）

基线：Windows 桌面版 `v1.0.64`，Arduino Uno，AVR Core 1.8.6。已提交的两份日志分别是 7.340 秒（两个适配库、V9 成功）和 24.195 秒（三个适配库、V9 回退到兼容编译）。它们的输入不同，不是同一工程的速度 A/B。用 NLCS21、TTS20、Agile Button 三个公开库和一个调用三者的独立样例，可以重现回退。按键库上游声明 `dot_a_linkage=true`；原版 V9 拒绝这种归档，随后桌面端再次走完整编译。

本机使用同一份 1.0.64 桌面 EXE、相同的 Uno 样例和库，分别加载原版和修复后的引擎代码。按钮值从点击测到进度浮层关闭且按钮恢复；新会话不等于清空操作系统文件缓存。

这是定位回退的小样本，不用于发布 p95 或全机型性能承诺。Uno 最终 `.hex` 与同一环境下独立运行 Arduino CLI 的结果逐字节一致。ESP32-S3 Core 3.3.6 的三个库在构建引擎内首次 73.30 s，改一行 9.28 s；未测桌面按钮或上传。对比 S3 应用镜像，每份镜像包含各自 ELF 的 SHA-256，及由此派生的尾部校验；独立 CLI 构建与 CK 构建的其余字节完全一致，官方 esptool 对 CK 的同一份 ELF 生成的完整 `.bin` 也逐字节一致。

自动回归不依赖上述厂商库。`tests/source-library-archive.test.mjs` 生成包含无用构造函数的双源文件库，验证未使用成员不会链接，修改主程序会复用归档，修改库会重建归档，最终 HEX 匹配官方 CLI。

## 扩展到其他库布局

`tests/library-linkage.test.mjs` 在同一个工程内使用四个独立的合成库。验证当前 MCU 无预编译包时使用源码、`precompiled=true` 同时链接源码和二进制、`precompiled=full` 命中后不再编译备用源码。样例同时包含有/无 `lib` 前缀的 `.a`、仅在适用时生效的 `ldflags`、子目录同名归档成员，以及旧式根目录和 `utility/`。二进制在测试当地生成，厂商无需提供材料。

每块板分别校验源码、切换为二进制、改主程序、原样重编和原地替换同名 `.a`。源码、二进制和替换后的固件分别与独立 `arduino-cli compile --clean` 比较。Uno 比较整个 HEX，另测官方前端交给 V9 执行的入口。S3 比较应用镜像有效内容，并分别验证镜像内 ELF 哈希、段校验和与尾部 SHA-256。这一组是引擎回归，不测桌面、上传和 p95。

使用测试配置指定的 Node 24 运行 `--test tests/library-linkage.test.mjs tests/source-library-archive.test.mjs`。`CK_ARCHIVE_AVR_CONFIG` 和 `CK_ARCHIVE_S3_CONFIG` 分别指向已安装 Uno 和 ESP32-S3 的测试配置，缺哪个板就明确跳过对应实编项。仅在已验证的平台配方上启用；活动的自定义链接脚本、动态库、薄归档及有歧义的二进制选择继续交给兼容编译。

2026-11-28 本机实编：Uno 1.8.6 和 ESP32-S3 3.3.6 的上述五个场景均走 V9，三次独立官方固件对照均通过。各取一次引擎收据，改主程序分别为 1.28 s / 9.11 s（均编译 1 个对象），原样重编为 0.44 s / 1.06 s（均编译 0 个对象）。这是单次观测，不是按钮端到端测速。配置 Uno 的全套测试 104 通过、3 跳过、0 失败；其中 S3 实编项另配工具链单独跑过。
