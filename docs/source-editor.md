# 工程内的积木 / 源码编程

打开或新建普通 CK 工程，在编辑区上方选择 **积木** 或 **源码**。两种模式共用工程、完整板卡配置、编译、上传、串口和输出日志。

## 切换与保存

- 首次进入源码页，会读取当前积木生成的 Arduino C/C++，可直接编辑。
- 编译、上传使用当前选中模式的程序。页面明确显示“编译当前源码”或“编译当前积木”。
- 手写源码单独保留；切回积木不会把任意 C++ 转成积木，再切回来也不会丢失手写内容。
- 从未手动修改的源码可以跟随新的积木生成结果。手动修改过后，需要主动点击“从积木更新”并确认，才替换为新生成结果。
- **Ctrl+S** 保存整个 `.ck` 工程：积木、手写源码、当前模式、具体板卡包、Core 和完整菜单选项都一起保存。另存为、工程检查点和恢复稿保留同样的源码数据。
- 离开时使用现有工程的未保存提示。旧工程没有源码数据时，正常以积木模式打开。

## 编辑与文件

提供行号、C++ 高亮、折叠、撤销、查找替换。**Ctrl+F** 查找，**Ctrl+H** 替换，**F7** 编译。

“导入 .ino”将 UTF-8 Sketch 导入当前工程，替换前询问确认。含 CK 板卡配置注释时同时恢复该配置，Core 不一致仍需核对。积木继续保留。

“导出 .ino”导出手写源码和板卡配置注释。在其他 Arduino 工具中使用时仍需选择正确板卡、Core 和依赖库。

编译期间锁住源码和模式切换；取消使用现有宿主进程树管理。输出日志继续实时更新，可复制与主动提交。能可靠识别的 Sketch 错误显示具体行号；库内部、链接器和未经映射的生成文件错误保留在日志中，不猜测手写源码的位置。

## 构建与范围

源码进入与积木相同的 `compile_sketch` / `upload_sketch` 宿主入口。V9 目标身份、工具链和依赖校验、增量调度、最终产物核验及兼容回退策略保持原有行为。首次新目标仍需编译必要依赖；速度以具体工程的端到端日志为准，不承诺所有源码和电脑具有相同耗时。

当前支持单文件 Arduino Sketch（最多 1 MiB UTF-8），可引用已安装的 C++ 库，不自动加载同目录其他 `.ino`、`.h` 或 `.cpp`。AI 积木助手、积木断点、运行轨迹及积木资源声明检查用于积木模式；源码模式通过编译日志定位问题。编译通过不等同于真机运行验证。

源码状态以版本化 `ckSource` 字段保存于现有 Blockly 工作区 JSON，通过注册的序列化器参与保存、另存、检查点、恢复稿和外观重建。未来或损坏的状态拒绝载入，避免静默丢失手写代码。
