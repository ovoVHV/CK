# 工程内的积木 / 源码编程

打开或新建普通 CK 工程，在顶部工具栏选择 **积木** 或 **源码**。两种模式共用工程、完整板卡配置、编译、上传、串口和输出日志。

## 切换与保存

- 首次进入源码页，会读取当前积木生成的 Arduino C/C++，可直接编辑。
- 编译、上传使用当前选中模式的程序。顶部标签标明当前模式，悬停提示说明编译对象。
- 手写源码单独保留；切回积木不会把任意 C++ 转成积木，再切回来也不会丢失手写内容。
- 修改积木后，源码会跟随更新。比如手写了一个辅助函数，再在积木里修改延时，两项修改都会保留。如果两边改了同一个延时值，源码页会列出差异，由你逐项选择“保留手写修改”或“采用积木修改”。冲突可以随工程保存，处理完才能用源码模式编译或上传。要完全用积木替换手写内容，可使用“从积木重新生成”。
- **Ctrl+S** 保存整个 `.ck` 工程：积木、手写源码、当前模式、具体板卡包、Core 和完整菜单选项都一起保存。另存为、工程检查点和恢复稿保留同样的源码数据。
- 离开时使用现有工程的未保存提示。旧工程没有源码数据时，正常以积木模式打开。

## 编辑与文件

提供行号、C++ 高亮、折叠、撤销、查找替换。**Ctrl+F** 查找，**Ctrl+H** 替换，**F7** 编译。

文件栏右侧的“源码操作”集中提供导入、导出和从积木重新生成。切换模式保留源码编辑器的光标、滚动位置及撤销记录。

“导入 .ino”将 UTF-8 Sketch 导入当前工程，替换前询问确认。含 CK 板卡配置注释时同时恢复该配置，Core 不一致仍需核对。积木继续保留。

“导出 .ino”导出手写源码和板卡配置注释。在其他 Arduino 工具中使用时仍需选择正确板卡、Core 和依赖库。

编译期间锁住源码和模式切换；取消使用现有宿主进程树管理。输出日志继续实时更新，可复制与主动提交。能可靠识别的 Sketch 错误显示具体行号；库内部、链接器和未经映射的生成文件错误保留在日志中，不猜测手写源码的位置。

## 构建与范围

源码进入与积木相同的 `compile_sketch` / `upload_sketch` 宿主入口。V9 目标身份、工具链和依赖校验、增量调度、最终产物核验及兼容回退策略保持原有行为。首次新目标仍需编译必要依赖；速度以具体工程的端到端日志为准，不承诺所有源码和电脑具有相同耗时。

主程序保存在 `.ck` 中（手写源码最多 1 MiB UTF-8），可引用已安装的 C++ 库。独立文件夹工程的目录与入口同名，例如 `小车/小车.ck`，目录内只能有一个工程入口。把 `Motor.h`、`Motor.cpp` 放在入口旁，或将模块放在 `src/` 及其子目录；在积木和源码模式中都可以通过工程文件树打开它们。有未保存的附带源码时，点工具栏「编译」会先保存这些文件，再开始编译；如果文件已被外部修改而无法保存，编译会停止。只改头文件也属于输入变化。普通单文件 `.ck` 不会扫描周围的文件，附带的第二个 `.ino` 不受支持。

每个附带源码文件最多 1 MiB，一个工程最多 256 个、合计 4 MiB。附带文件单独保存在磁盘上：把工程交给别人时，请复制整个目录；“导出 .ino”只导出主程序和板卡配置注释。可参考[多文件闪灯示例](../desktop/examples/多文件闪灯)。

AI 积木助手、积木断点、运行轨迹及积木资源声明检查用于积木模式；源码模式通过编译日志定位问题。编译通过不等同于真机运行验证。

源码状态以版本化 `ckSource` 字段保存于现有 Blockly 工作区 JSON，通过注册的序列化器参与保存、另存、检查点、恢复稿和外观重建。未来或损坏的状态拒绝载入，避免静默丢失手写代码。
