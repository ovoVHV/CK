# CK AI：聊天、密钥与上下文

适用版本：9.1.0-alpha.39。点击编程页工具栏的 **AI** 打开现有侧栏；聊天记录和设置都在侧栏内。

## 连接模型

点击右上角设置，填写支持工具调用的 Chat Completions API 地址、模型名称和密钥。设置对所有工程生效。修改 API 地址时会清空输入框内旧密钥，需重新填写，避免把原密钥发送到其他服务。

勾选“在这台电脑记住密钥”后，密钥使用 Windows 当前用户的 DPAPI 加密保存；下次启动可继续使用。可以直接替换密钥，也可以取消记住后保存，删除已保存密钥并改为仅在当前会话使用。密钥不会写入工程、聊天消息或普通工程导出文件。

## 聊天记录

右上角时钟图标打开当前工程的聊天列表。“＋”创建新的聊天，不删除旧聊天。列表可切换、重命名和删除，删除需要在面板内确认。消息、未发送草稿和摘要自动保存在当前 CK 数据目录的 `state/ai-assistant-v1`；看到“已保存到本机”代表写入已完成。

打开另一个工程时切换到该工程的聊天。已保存工程再次打开时恢复其最近的聊天。未保存的临时工作区按当前工作区身份管理；正式工程应先保存，再建立需要长期保留的聊天。聊天不是工程的一部分，不随工程导出给别人。

历史中的修改方案只保留文字，不恢复可以直接执行的预览、旧积木授权或撤销状态。继续修改时，AI 必须重新读取当前工程并生成新的预览。编译、应用和撤销结果会作为操作记录显示。

## 上下文预算

| 设置 | 默认 | 用途 |
|---|---:|---|
| 上下文预算 | 32,768 tokens | 一次请求允许携带的工具定义、提示词、历史资料和回复总预算 |
| 单次回复预留 | 8,192 tokens | 给模型的回复或工具参数预留空间，不是每次必然用满 |
| 自动压缩 | 开启 | 预计输入接近可用输入预算的 80% 时整理旧对话或完整工具交互 |

请根据模型服务商实际支持的长度设置预算；CK 中填写更大的数字不会扩大模型上限。上下文预算可设置为 16,384–262,144，回复预留为 1,024–32,768，且不超过总预算的一半。

本轮复杂方案测试包含默认32k预算不足的样本，完整复杂用例批次使用64k。若模型支持，可将复杂多任务方案的上下文预算设置为65,536；这仍不保证任意需求一次完成。较大预算可能增加每轮发送的内容和费用，实际用量会记录，不承诺固定token节省比例。

模型连续三次回复超出长度时，任务停止，避免继续反复消耗。截断的工具调用不执行，原工程不变。完整回复会重置连续次数；遇到该提示，可拆分需求，或在模型支持时调整单次回复预留后重新发送。

压缩后保留摘要和近期消息，完整原聊天仍存在本机。AI 的 `read_chat_history` 工具可按需检索原消息，并分页读取较长消息，避免每轮发送整段历史。摘要只作为历史资料，当前板卡、积木字段和编译结果仍以本次读取为准。工具调用与对应结果按完整交互处理，不拆散配对记录；暂存的未应用方案保持完整。

聊天历史、库说明和错误摘要可能调用所选模型，产生相应 token 用量；已核对结构和暂存节点直接由程序整理，不为每段节点另发摘要请求。侧栏的上下文数字为保守估算，可能与不同模型的 tokenizer 不同；服务商返回实际用量时另外显示。没有返回用量就不虚构账单。摘要可能遗漏信息，重要约束可以让 AI 回看原聊天。

## 按需使用库资料

CK 先列出当前可用库、按能力搜索积木，再按需读取真实字段和库文档。库作者继续在 `ck-blocks.json` 描述功能、参数、返回单位、初始化、阻塞行为、硬件资源、限制与错误恢复。无需另写 MCP 服务、AI 脚本或自行生成质量报告。

同一次任务中的重复只读查询可以引用上下文里已有的完整结果。若历史已压缩、工程变化或开始新请求，会重新核对相应资料。省 token 不等于跳过结构验证、编译或硬件复核，也不保证任意复杂需求一次成功。

## 取消与恢复

点击停止会取消当前模型请求或候选编译，并等待原生进程结束后显示已停止。切换工程、聊天或重新加载后，旧预览不再有效。存储采用完整文件替换和版本检查；另一个窗口已更新同一聊天时拒绝覆盖。损坏记录保留原文件并提示，其他可用聊天可继续使用。

聊天和摘要是本机资料；发送时所需上下文会送到你选择的模型服务。已识别的密码字段和连接密钥会被脱敏，其他私人内容请自行判断是否应发送。


## 第二阶段：先验证，再应用

发出搭建或修改需求后，AI 可以先列出简短计划，再分段搭建候选方案。候选工作区与当前工程分离；软件检查积木结构，在当前完整板卡配置和 Core 版本下执行本地编译。第三方库仍使用已安装的积木和生成器，不要求作者为报错专门增加 AI 字段。

如果编译失败，AI 读取真实诊断，最多再修复两次。总计最多三次候选编译，每次最多四分钟，整个任务最多十二分钟；轮次、工具调用和上下文另有有限预算。达到任一上限会停止，不循环无限重试。主聊天会先查已有能力，必要时补建最小积木库，通过独立试编译后自动加载，再继续原工程。库与工程各自有三次编译预算，每任务最多补两个库；不会自动下载未知驱动或上传固件。

侧栏中的“任务过程”可展开查看计划和实际执行记录。“本地验证”保留每次编译状态、耗时和日志。能证明源文件身份的诊断会对应到候选积木；无法可靠映射时保留原始错误，不猜测位置。

只有本地编译成功的候选才显示可应用的修改预览。**应用修改**将已预览的候选作为一笔可撤销操作写入当前工程；**应用并编译**会另外正常编译当前工程以建立其自身的固件结果。两者都会先保存修改前检查点。候选固件不会成为工程的上传依据，也不会自动更新工程的成功记录。

用户修改工程、切换板卡或外部改变库列表，会使旧请求或预览失效。当前任务自己安装的库会经过工程、板卡和其他库内容检查，更新可用积木后继续。一次撤销可以恢复应用前的完整工作区；失败和取消都不修改原工程积木；已经提交安装的库会保留，并单独记录。重启后保留验证的文字记录，完整临时日志和可执行预览不作为持久化授权恢复。

编译通过仅证明当前工具链接受生成代码，不保证程序符合全部需求，更不代表传感器、接线、电机等实体硬件运行正确。复杂功能仍需检查逻辑并由用户主动上传验证。


复杂任务压缩时，已核对的字段、选项、连接、模板、计划和暂存节点由程序以精确结构保留；摘要不承担重建这些接口的职责。节点可按 key 精确查询或分页回查。暂存而未放置的节点会阻止提交，避免只编译部分方案。AI 还可以读取暂存积木实际生成的代码，核对默认参数、周期和安全条件；代码检查不等于行为或真机测试。结构中的“有输出”和“输出类型未限制”分别表示，避免误判第三方或通用值积木。

发现局部错误时，AI 可以修订已有暂存节点，软件会同步重建受影响的候选连接，避免重新发送整套方案。结构校验失败则保留上一次完整候选；明确废弃且未被引用的草稿节点可以删除。压缩会移除已进入精确状态的重复节点参数，完整聊天仍保存在本机。

## 第三阶段：按固定条件验证复杂工程

直接在编程助手描述需求，例如“保留现有采样、急停和心跳，只修改控制阈值，并检查行为”。AI 可以按需读取工程地图，查看变量引用、函数、当前使用的库以及作者声明的硬件用途；这些声明不算真机证明。

复杂任务会先固定验收清单。界面分别显示“场景通过”“断言失败”和“待验证”；点击详情查看输入、时间窗口以及期望/实际结果。编译成功后，具备支持条件的候选固件才执行行为检查。失败结果回传给 AI 局部修复，同一任务不能换测试或降低标准；共用最多三次工程候选编译预算。需求变化时请新发任务。

当前指令模拟支持 **Arduino Uno / Nano 的 16MHz ATmega328P**，包含 GPIO、定时器、AVCC 参考 ADC 和 USART0 的有限行为。每个场景从 MCU 复位开始，最多六个场景、单场景五秒、合计十二秒虚拟时间；最多128项断言。执行在独立 Worker 中，有墙钟时间上限并可停止。模拟实际编译的 HEX，不运行模型临时编写的桌面测试脚本。ESP32、Mega、Nano ATmega168 和未覆盖外设保留真实编译检查，行为状态保持待验证。

模拟不代表实体硬件。真实接线、外设协议、电气特性和未覆盖的边界条件始终需要另行验证。固定测试由模型依据需求提出，用户应检查其是否覆盖关键条件；有限场景通过不能保证全部逻辑正确。中文串口文本按 UTF-8 解码，已识别的私密值会在反馈和聊天记录中脱敏。

停止或关闭后，主聊天可保留加密任务草稿。重新打开时点击 **继续任务**，软件检查当前工程、板卡配置与所有加载库的内容身份，重新建立预览并编译验证。身份变化会拒绝自动续接并保留草稿；旧通过记录不能直接授权应用。只有明确确认应用才修改工程。草稿使用当前 Windows 用户加密；独立“制作库”模式本轮不保存可续接制作进度。

需要理解或改进库时，AI 可分页只读当前加载库的源码。对 CK AI 声明式库，修订会建立新包、新积木类型和独立头文件，保留来源内容摘要与原许可。原库和其他工程不自动迁移；当前工程的引用更新仍经过编译、验收和确认。任意第三方库暂不自动改写，库内未知硬件实现也不能凭推测补全。

## 第四阶段：精确读取与长任务恢复

已有工程可以先让 AI 读取实际生成代码理解逻辑，再按字段值、变量名或积木类型定位目标；按 ID 批量读取父级、输入或后继连接，也可限定子树。每次仍返回真实字段和连接，只有实际读到的积木才可修改。只读代码不允许绕过积木编辑或直接写入 C++。这些读取使用 Blockly 已有结构，普通第三方库无需增加 AI 回调。

压缩后的草稿保留精确字段编辑、节点图、放置位置及混合修改顺序，避免只记住修改数量、忘记具体内容而重复搭建。取消恢复保留最近的真实失败反馈；损坏的图与编辑映射会拒绝恢复。历史失败是修复资料，不是通过证据，恢复后仍需重新编译和执行适用验证。单纯只读聊天不会产生空的任务恢复卡。

减少重复读取能够降低部分多轮任务的输入用量，实际表现仍取决于模型、提示、项目和验收规模。累计 Token 包含每轮上下文重发，不等于单次上下文或计费金额；成功的有限样本不代表任意复杂项目均能完成。

验收计划锁定前，还会检查本计划声明的外部输入是否在每个场景的0ms明确初始化。漏写按钮、急停等输入时拒绝锁定并返回缺失项，允许AI先修正计划；锁定后仍不能更改条件。该检查不代表自动识别了所有硬件输入，未建模电气状态不作通过结论。

复杂失败时，压缩上下文只呈现精确失败断言，完整日志与全部结果可由read_task_feedback按页回读，固定验收条件不会随压缩改变。少量已读目标的字段、连接和短代码页可保留，减少反复查询。较大的真实草稿或验收仍可能超过预算；软件会停止并保留草稿，不静默提高预算或丢掉必要状态。

alpha.41 实测仍存在模型测试设计偏差：一次只要求修改阈值的任务中，模型为满足自建测试多加了启动等待，自己的场景通过，但独立检查未通过。软件的“场景通过”只对应列出的固定断言，不代表模型已完整理解需求。该样本没有应用到原工程；本版不宣称复杂工程资格全部通过。

## 当前板卡与后续新增板卡

AI 编程、制作/补充积木库、候选编译跟随工程当前的完整 FQBN、精确板卡包、Core 版本和菜单选项。软件已接入的板卡共用这条链路，后续导入且通过 CK 校验的板卡包无需另加 AI 白名单。Core 和工具链仍须就绪，现有库的适用架构也必须相符。AI 可用并不等于该目标已经获得原生提速资格。

AI 可调用 `get_board_capabilities`，按需分页读取当前板卡的引脚、资源占用、共享规则、总线映射和资料来源。原有菜单条件和风险会完整保留。自定义载板不能仅因编译 FQBN 相同而借用内置板卡引脚。缺少元数据表示未知，不能假定 Uno 的引脚和 ADC 范围适用于其他芯片；可补充板卡资料或库声明帮助 AI。资料是参考数据，不是实机验证。

行为模拟能力单独查询。当前模拟器只覆盖已经说明的 Uno/Nano 配置；ESP32、Mega 和其他板卡仍可进行 AI 编程、补库和真实本地编译，无法模拟的验收项保留为待验证。生成的库仅声明本次目标兼容，不能把一次编译成功扩大成全部板卡、全部功能通过。切换板卡/Core/参数或更新当前能力资料时，进行中的任务会停止，须基于当前目标重新发送。

## 第五阶段：限制修复扩大范围

若第一次送验的候选只修改现有积木字段，CK 会固定这些字段作为本任务的修复范围。数值仍可纠正，但不能在修复时新增变量、积木或连接，也不能改其他字段、补库或改库。界面显示“修复范围 · 仅 N 个既有字段”。这个限制会保留到压缩、取消和关闭软件后的恢复流程；重置草稿不能解除限制。

如果模型发现固定测试与需求矛盾，应该具体说明并停止。修改需求时可另发消息建立新任务；不要让模型通过改变原有逻辑来迎合错误测试。软件同时检查实际候选的序列化内容，第三方积木的字段联动若改动其他状态，会在送验前拒绝，原工程不变。

结构搭建任务不被伪装成字段任务，继续经过原有结构、编译和适用的行为验证。此限制从首次候选确定范围，不是自然语言需求解析器，也不证明首次候选或所有结构任务都正确。

需要验证输出保持不变时，模拟器支持窗口内零次跳变；若窗口内引脚未始终处于输出模式，会判失败。不能用未驱动的引脚证明“输出稳定”。
