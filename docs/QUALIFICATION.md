# V9 发布门禁

V9.0 建立可构建、可测试的独立候选；不等同 V9.1 全部集成、V9.2 性能和兼容验收、V9.3 默认发布。

| 门禁 | 最低证据 | 当前原则 |
|---|---|---|
| 新编辑 | 同桌面 IPC，至少 30 次，nearest-rank P95 ≤ 20 秒 | 保留每个样本，不剔除慢样本；冷启动另列 |
| 历史恢复 | 至少 20 次 A→B→A，恢复请求中位数 ≤ 10 秒 | 完整资产及最终产物验证不能省略 |
| 相同源码 | 至少 20 次，中位数 ≤ 5 秒 | GCC/链接/镜像任务为零；不能以组件时间代替 IPC |
| 兼容性 | 至少两台不同 Windows 机器、多工程和库组合 | 单机结果不能填补第二台机器证据 |
| 正确性 | 官方 clean 的 CPP、编译数据库、对象和十个交付文件 | 不只看编译退出码 |
| 生命周期 | 多工程/同工程并发、取消、崩溃、重启、缓存破坏、升级失效 | 失败不授权，未证实退出的工作区不得复用 |
| 回退 | 功能关闭/目标不支持/请求未执行可走 v6；其他错误明确失败 | 未知执行状态不能并发启动另一条构建路径 |
| 可复现性 | 源码版本、环境、完整样本、构建命令、SHA256 清单 | 报告区分集成检查与性能资格批次 |

每次优化提交均回答 Correctness、Task Reduction、Validation Cost、IPC Latency、Regression、Fallback、Reproducibility。回归失败、取消和中断样本也保留；它们是失败率证据，不伪装成成功的延迟数据。

V8-G 的五次最终样本和独立确认批次均保留，不能从其推断 V9 的 P95。当前 T1 范围及尚未覆盖的条件必须随预览和发布文档说明。
