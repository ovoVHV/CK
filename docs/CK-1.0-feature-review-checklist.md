# CK 1.0 现有功能审核清单

更新时间：2026-08-26。

这份文档是给产品审核使用的“老板版功能总表”：只列当前代码中已经存在、可以体验或已经形成内部工具链的能力，并把入口、预期结果和限制写清楚。更细的实现证据与安全边界继续以 [`current-feature-inventory.md`](current-feature-inventory.md) 为准。

本轮不是只复读旧文档：已重新核对主页、工作区顶栏、积木右键菜单、工程体检、库/Core/板卡管理、恢复与提交窗口、前端服务和 Tauri 构建/上传入口。没有实际动作的主页占位项继续列在“未交付”，后台自动保护则单独写明触发时机。

> 本表中的“完成”表示功能已实现并有代码或测试证据，不等于已经满足公开正式分发。当前 CK 1.0 的准确口径仍是：**本机验证／封闭测试候选**。Windows 安装包尚未完成可信代码签名和时间戳；macOS/Linux 也尚无与 Windows 等价的原生验收。

> 当前源码晚于上一份最终发布证据清单，因此旧的 [`v1-release-evidence-manifest.json`](../artifacts/release/v1-release-evidence-manifest.json) 只能作为历史记录。功能审核可以继续，但若要形成新的“封闭测试可发布”裁决，仍需按新源码重新冻结并执行完整 Gate、生产构建、原生冒烟和真板闭环。

## 1. 审核方法和状态口径

- `✅ 已完成`：用户链路或正式开发者链路已经接通，并有自动化、原生窗口或真板证据。
- `🟡 有边界`：功能可用，但只对明确板卡、配置、证据或第一版范围负责。
- `🧪 内部工具`：已有可靠脚本、报告或 SDK 能力，但不是普通用户的桌面按钮。
- `⏸ 未交付`：只记录了设计、Schema 或后续计划，不能对外说已经上线。
- “审核”栏保留空框，审核人实际体验后可以在 Markdown 中改为 `[x]`。

### 2.1 最容易漏掉的 8 个入口

1. **文件／更多**：库管理器、工程检查点、上一个可用版本、工程诊断包、项目验收报告都在这里。
2. **板卡设置**：完整 FQBN、Core 菜单、普通重建、彻底刷新、重编译和重烧录都在这里；这里只改当前板卡配置，不切换物理板卡。
3. **串口下拉**：选择／断开端口和 ESP32 真机体检；真机体检会短暂复位，但不写 Flash。
4. **普通上传右侧下拉**：调试上传；只有先右键积木添加断点后才可用。
5. **视图**：工程体检、串口监视、代码预览、运行轨迹、简洁／工程视图和三态主题。
6. **工程体检**：构建路径、Fast/原生回退原因、资源预算、增长解释、真机证据、精确引脚风险和可操作错误卡。
7. **可执行积木右键菜单**：添加／取消软断点；断点会随工程保存。
8. **库管理器／新建工程选板页**：前者管理 CK 积木包和 Arduino 源码库，后者管理第三方板卡、Core 环境、四级板卡护照和本机 compile-only 验证。

另外一批功能**没有按钮**：滚动恢复稿、编译/上传前保护检查点、源码到积木映射、Exact 判定、Fast 资格校验、缓存回收、串口互斥、上传产物清单、芯片/Flash 错配阻止和未知积木保险箱都在满足条件时自动执行。

## 17. 建议审核顺序

### 17.1 十分钟桌面主流程

1. 在主页切换浅色/深色/跟随系统，检查工程搜索、网格/列表和工程存储位置。
2. 新建 C6 工程，确认板卡只能在外部选择；进入后打开“板卡设置”，查看完整 FQBN 和菜单项。
3. 拖入几个积木，使用底部全局搜索，确认结果带分类/库来源；打开代码预览并复制。
4. 分别点击“编译”和“普通上传”，确认仍是两个独立一键按钮。
5. 打开“工程体检”，查看构建路径、资源预算、引脚和错误卡；收起后确认不会留下挡路的大侧栏。

### 17.2 编译错误 → 积木定位

1. 新建临时工程，在“循环”分类放入 `goto label1`，暂时不放匹配的“标签 label1”。
2. 点击“编译”，不要上传。
3. 输出日志应出现错误卡；点击“定位积木”，工作区应居中并高亮该 `goto` 积木。
4. 在同一函数/流程中加入“标签 label1”，重新编译，错误应消失。

### 17.3 资源增长解释

1. 在同一完整 FQBN 下先成功编译一个简单工程。
2. 增加 Wi-Fi 或其他有明显库依赖的积木，再次成功编译。
3. 打开“工程体检 → 资源预算 → 为什么变大？”。
4. 有完整 linker map 时应显示库/Core/生成代码/残差；证据不足时应诚实退回总变化。

### 17.4 第三方生态

1. 打开“库管理器 → 本地导入”，导入 [`examples/importable-packages`](../examples/importable-packages) 中的标准积木包和 Arduino 深层原生库。
2. 查看“已安装 → 质量报告”，确认阻止项、警告、哈希和运行时状态分开显示。
3. 新建工程页打开“第三方板卡”，导入 C6 示例板卡包，查看四级板卡护照和自动 compile-only 认证。
4. 解压 [`CK-Extension-SDK-1.0.0.zip`](../artifacts/release/CK-Extension-SDK-1.0.0.zip)，依次体验 `ckpkg create / validate / test / compile / pack`。

### 17.5 恢复和提交

1. “文件/更多 → 工程检查点”手动保存、恢复并删除一条检查点。
2. 普通上传成功后打开“上一个可用版本”，体验比较、恢复工程、恢复固件和完整恢复入口。
3. 打开“工程诊断包”，分别查看三档源码范围和默认脱敏。
4. 打开“项目验收报告”，导出 JSON、可打印 HTML 和一份只读 `project.ckpkg`。
