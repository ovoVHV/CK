# 编译日志接收服务

用户在 CK 编译输出区主动点击“提交本次日志”，检查脱敏预览后才联网。
客户端保留最多 8 次前台构建的有界日志快照；静默构建不自动上报。编译路径不进行反馈网络或磁盘写入。编译+上传在进入上传传输前冻结编译日志，不收集串口输出。

服务仅监听 `127.0.0.1:8793`，由现有 Caddy HTTPS 代理 `/ck-feedback/v1/*`，覆盖客户端自带的 `X-CK-Peer` 为实际连接 IP。没有公开日志读取、列表、修改或删除 API。日志数据库在 `/var/lib/ck-feedback/feedback.sqlite3`，不在网站目录，独立低权限用户运行。

## 防刷和一次提交

- 宿主生成每次编译的随机报告 UUID，保存不可变快照；WebView 只能传运行 ID，不能传任意日志或文件路径。
- 服务端签发 10 分钟有效的 HMAC 凭据，绑定报告 ID、SHA-256、匿名安装标识和来源网段；要求 SHA-256 工作量证明。
- SQLite 唯一键与事务保证并发、重复点击、网络重试和服务重启都只保存一份。回执包含报告编号。相同 ID 修改内容拒绝。
- 每安装每小时最多 6 份、每天 20 份；每 IP/IPv6 /64 每小时 10 份、每天 40 份；全站每小时 60 份、每天 300 份。另有挑战和请求入口限流。
- 请求最大 512 KiB，日志最多 240 KiB，总有效日志最多 256 MiB；工作线程最多 8 个，数据库回执最多 10 万条，达到上限停止接受新报告。
- 日志正文保留 30 天并每日清理，去重回执继续保留，避免到期后重新存入旧报告。IP 与安装 ID 仅保存带服务器密钥的摘要，不记录原文 IP。

这是匿名反馈服务。开源客户端不能证明“攻击者真的完成了一次编译”，不把客户端内置密钥当安全边界。防护限制重复写入和单点滥用；大规模分布式网络攻击仍需服务商/CDN 防护。严格配额可能影响同一校园或公司出口，可根据实际反馈调整。

脱敏采用诊断行白名单，再过滤常见秘密字段、引号文本、本地路径、网络地址和常见密钥形式。不上传工程/源码文件。第三方工具输出无法保证识别所有个人信息，界面要求用户确认准确预览。

## 部署与检查

Python 3.10+，标准库，无额外 pip 依赖。在已有 HTTPS 站点的服务器上传本目录到 `/opt/ck-feedback`，执行 `sh deploy-local.sh`。脚本先运行测试，建立服务，验证 Caddy 配置并备份后重载；失败回滚配置。不要直接把 Python HTTP 服务暴露到公网。

```sh
python3 -m unittest -v test_server
systemctl status ck-feedback
systemctl status ck-feedback-maintain.timer
```

只有服务器管理员通过 SSH 查看报告：

```sh
sudo -u ck-feedback python3 /opt/ck-feedback/server.py --list
sudo -u ck-feedback python3 /opt/ck-feedback/server.py --export 报告编号
```

导出的 JSON 包含板卡、CK 版本、任务次数和分阶段耗时，可按报告编号与用户反馈对应。请不要把数据库或导出文件放进网站公开目录。退出使用时停用 `ck-feedback.service` 和维护 timer，并移除 Caddy 中单独的反馈路由；不影响更新下载路由。
